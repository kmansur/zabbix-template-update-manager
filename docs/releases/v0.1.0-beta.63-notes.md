# Zabbix Template Update Manager v0.1.0-beta.63

**Laboratory prerelease candidate — not approved for production.**

## Installer and runtime simplification

The root-level `install.sh` now prepares and validates private runtime directories automatically, including the new `cache/` directory. The former `tools/ztum-runtime-setup.sh` is retired.

```bash
sudo bash install.sh --runtime-check  # read-only, for installed hosts
sudo bash install.sh --upgrade        # controlled code-only upgrade
```

Upgrades require a newer `VERSION` than the installed module. The installer keeps private rollback backups and prints a backup identifier. A code rollback does **not** undo a Zabbix template import.

## Security hardening

- The catalog, immutable-template and immutable-commit-history caches moved from `/tmp` to private runtime storage.
- Historical REST requests now have a bounded 12-second timeout; any missing history continues to block unattended updates.
- Cache-directory mode, ownership and symlinks are checked; there is no unsafe temporary fallback.
- Lock path overrides reject relative and unsafe paths.
- GitHub first-party actions are pinned by immutable commit SHAs, with an automated guard.
- Documentation clarifies Super Admin-only access and warns that rollback exports may include sensitive values.

## Validation boundaries

Automated CI, security, release and field tests must be checked before this candidate is published. In particular, validate fresh install, beta.62 → beta.63 upgrade, same-version refusal, module-code rollback, catalog display, batch preparation, safe update and rollback in both Zabbix 7 and 8 laboratories.

This release does not change the single Zabbix import boundary or allow automatic retries or template rollback. No runtime SQL access, Composer dependency or new daemon is introduced.
