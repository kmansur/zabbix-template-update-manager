# Zabbix Template Update Manager (ZTUM) v0.1.0-beta.62

**Public laboratory prerelease — NOT approved for production.**

ZTUM is an independent, open-source native Zabbix frontend module for discovering, comparing, installing, updating and rolling back official Zabbix templates. It is not an official Zabbix LLC product.

## What's new in beta.62

- A single root-level `install.sh` for minimal runtime-only installation, with automatic Zabbix 7/8 frontend discovery and PHP-FPM account detection when unambiguous.
- An explicit **code-only** `install.sh --upgrade` workflow requiring a newer source version; creates root-private, SHA-256-inventoried backups.
- Explicit `install.sh --rollback BACKUP_ID`, with mandatory SHA-256 and exact-file-inventory preflight checks before replacing installed module code.
- Manual, read-only **Check for ZTUM updates** against published GitHub releases, including prereleases; no automatic installation or download.
- Consistent **Super Admin-only** access across module actions, including read-only screens.
- Updated installation guides and automated frontend/security/release-package checks.

## Validation performed

- GitHub Release workflow [38082038614](https://github.com/kmansur/zabbix-template-update-manager/actions/runs/38082038614) succeeded, including disposable Zabbix 7.0 and 8.0 frontend smoke tests, PHPStan, Python checks and release archive creation.
- Both published ZIP and TAR.GZ files were verified against the published `SHA256SUMS` asset.
- On a Debian 13 / Zabbix 8 laboratory, a beta.61 → beta.62 code upgrade, code rollback to beta.61 and re-upgrade to beta.62 succeeded. Three backups passed SHA-256 validation; modified-file and extra-file backup copies were rejected before code replacement.
- On a Debian 13 / Zabbix 7.0.31 laboratory, beta.62 catalogue, template filters and operation history rendered correctly, and a beta.61 code backup passed SHA-256 validation. A complete Zabbix 7 code rollback was not demonstrated.

## Install and upgrade (laboratory only)

Use the immutable tag instead of a moving development branch:

```bash
cd /usr/local/src
git clone https://github.com/kmansur/zabbix-template-update-manager.git
cd zabbix-template-update-manager
git checkout v0.1.0-beta.62
sudo bash install.sh
```

For existing installations, schedule a maintenance window, confirm that no ZTUM operations are running, preserve external backups and review the current code before using:

```bash
sudo bash install.sh --upgrade
```

The command prints a backup ID. Rollback of **module code only** is available through `sudo bash install.sh --rollback BACKUP_ID`, after verifying the backup. Rollback does **not** undo template imports or Zabbix database writes.

See [installation documentation](https://github.com/kmansur/zabbix-template-update-manager/blob/main/docs/install-from-source.md) for details. Documentation on `main` may include post-release corrections and does not change this immutable tag.

## Limitations and security status

- **Not production-ready.** Use disposable or non-production Zabbix instances.
- Authenticated CSRF differential, complete HTTP interrupted-write recovery, controlled activation-failure injection, and broader Linux-distribution testing remain pending.
- Installer SHA-256 manifests protect against accidental/local file changes but are not external cryptographic signatures.
- The installer does not drain active PHP-FPM/ZTUM operations and does not auto-update templates or the ZTUM module.
- Zabbix frontend smoke coverage does not constitute full production compatibility certification.
